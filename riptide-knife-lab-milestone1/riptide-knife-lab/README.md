# RIPTIDE: KNIFE LAB, milestone 1

A client-side Fabric mod for Minecraft Java 1.21.11.

## What milestone 1 does

- **Keys:** J opens Knife Lab. G inspects the held knife. Both are rebindable under Options > Controls > Key Binds.
- **Knife Lab screen:** pick one of three knives (Butterfly, Karambit, M9 Bayonet), and toggle sword replacement and the inspect animation.
- **Sword replacement:** a held vanilla sword (each of the six toggleable) draws as the selected knife's 3D model. Only the client view changes. The stack, damage, enchantments, and inventory are untouched.
- **Inspect:** G spins the held knife for 2 seconds. It is blocked when no knife is equipped, while a screen is open, while using an item or attacking, or when the feature is off.
- **Settings:** saved to `config/riptide-knife-lab.properties`.
- **Texture:** one original finish, "Tidal Steel", generated by `tools/generate_assets.py`. No third-party art.

## Status: not yet compiled against Minecraft

This was written in an environment without network access, so Gradle, Fabric Loom, Fabric API, and the Minecraft jar were never downloaded.

- **Verified:** the core logic (knife list, settings, persistence, inspect state machine) compiles with no warnings and passes 29 checks in `tests/CoreTests.java`. The generated JSON models and item overrides are valid and reference existing files.
- **Not verified:** all Minecraft-facing code (keys, screen, renderer mixin). Expect a few fixes on the first build. The list below shows where.

## Build

1. In `gradle.properties`, replace `fabric_version` with the Fabric API build for 1.21.11, and confirm the other versions at https://fabricmc.net/develop. The placeholder fails the build on purpose.
2. Generate the Gradle wrapper: `gradle wrapper`, or let IntelliJ create it.
3. Run `./gradlew build`. The JAR appears in `build/libs/`.
4. If Loom reports obfuscated classes for this version, add `mappings loom.officialMojangMappings()` under `dependencies` in `build.gradle`.

## Test the core logic (no Minecraft needed)

```
javac -d build/core src/main/java/dev/riptide/knifelab/core/*.java tests/CoreTests.java
java -cp build/core CoreTests
```

## Regenerate assets

```
python3 tools/generate_assets.py
```

## Check on the first build

- **Key API:** `KeyBinding`, `KeyBinding.Category.create`, and `getBoundKeyTranslationKey` are written with Yarn-style names. If the build uses Mojang names, rename them (`KeyMapping`, `consumeClick`, and so on).
- **Held-item mixin:** `HeldItemRenderer.renderItem` and its parameters. The held-item rendering was refactored in recent versions, so this is the most likely fix.
- **Tick progress:** `RenderTickCounter.getTickProgress(boolean)` in `KnifeRenderHooks`.
- **Custom model data:** the `CustomModelDataComponent` constructor, and the `minecraft:select` / `custom_model_data` format in `assets/minecraft/items/*_sword.json`.
- **Screen:** `render` and background drawing.
- **Knife pose:** the models inherit the `item/handheld` first-person transform. Tune the position and rotation in-game.

## Known limits

- The swap is client-side. Other players still see a vanilla sword.
- Another mod or resource pack that overrides `assets/minecraft/items/*_sword.json` breaks the swap. This is the conflict case the spec describes. Detection comes later.
- A sword in the offhand that matches the main hand is drawn as a knife too.
- The Karambit ring and blade curve are stepped approximations. Replace them with better geometry in milestone 5.
